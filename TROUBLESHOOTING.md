# Диагностика проблем с деплоем на GitHub Pages

## Если страница не отображается или показывает старое содержимое:

### 1. Проверьте настройки GitHub Pages

1. Откройте ваш репозиторий на GitHub
2. Перейдите в **Settings** (Настройки) → **Pages**
3. В разделе **Build and deployment** → **Source** должно быть выбрано: **GitHub Actions**
   - ❌ НЕ должно быть "Deploy from a branch"
   - ✅ Должно быть "GitHub Actions"

### 2. Проверьте, что workflow отработал успешно

1. Перейдите во вкладку **Actions** в вашем репозитории
2. Найдите последний запуск workflow "Deploy to GitHub Pages"
3. Убедитесь, что он **успешно завершился** (зелёная галочка ✓)
4. Если есть ошибки — нажмите на запуск и посмотрите логи

### 3. Проверьте разрешения для Actions

1. Перейдите в **Settings** → **Actions** → **General**
2. Прокрутите вниз до **Workflow permissions**
3. Убедитесь, что выбрано: **Read and write permissions**
4. Сохраните изменения

### 4. Проверьте ветку по умолчанию

1. Перейдите в **Settings** → **Branches**
2. Убедитесь, что **Default branch** — это `main` (не `master`)
3. Если нужно, измените и сохраните

### 5. Убедитесь, что файлы на месте

В вашем репозитории должны быть:
- ✅ `.github/workflows/deploy.yml`
- ✅ `public/.nojekyll`
- ✅ `public/404.html`
- ✅ `vite.config.js` с `base: './'`

### 6. Проверьте URL

После успешного деплоя сайт доступен по адресу:
```
https://<username>.github.io/<repo-name>/
```

⚠️ **Важно**: если репозиторий называется не `<username>.github.io`, URL будет с именем репозитория!

Примеры:
- Репозиторий `workshops` → `https://username.github.io/workshops/`
- Репозиторий `username.github.io` → `https://username.github.io/`

### 7. Сбросьте кэш браузера

Попробуйте:
- Открыть в режиме инкогнито (Ctrl+Shift+N / Cmd+Shift+N)
- Добавить `?v=2` к URL: `https://your-url/?v=2`
- Очистить кэш браузера

### 8. Проверьте консоль браузера

1. Откройте ваш сайт
2. Нажмите F12 (или Ctrl+Shift+I / Cmd+Option+I)
3. Перейдите на вкладку **Console**
4. Посмотрите, есть ли ошибки (красные сообщения)
5. Если есть ошибки — скопируйте их и покажите мне

### 9. Проверьте Network tab

1. Откройте DevTools (F12)
2. Перейдите на вкладку **Network**
3. Обновите страницу (F5)
4. Посмотрите, какие запросы выполняются
5. Проверьте, нет ли ошибок 404 или CORS

### 10. Принудительный перезапуск workflow

Если ничего не помогает:
1. Перейдите в **Actions** → **Deploy to GitHub Pages**
2. Нажмите **Run workflow** → **Run workflow** (кнопка справа)
3. Дождитесь завершения

## Частые проблемы и решения

### Проблема: "Page build failed"
**Решение**: Проверьте логи в Actions, обычно это проблема с зависимостями или синтаксисом.

### Проблема: Страница 404
**Решение**: 
- Убедитесь, что URL правильный (с именем репозитория)
- Проверьте, что `base: './'` в vite.config.js

### Проблема: Белый экран
**Решение**: 
- Откройте консоль браузера (F12)
- Посмотрите ошибки JavaScript
- Проверьте, что все файлы загрузились (Network tab)

### Проблема: CORS ошибки при загрузке CSV
**Решение**: 
- Google Sheets API должен работать без CORS
- Проверьте, что таблица публичная (доступна по ссылке)
- Попробуйте открыть CSV напрямую: `https://docs.google.com/spreadsheets/d/12RhQZkMXbDLoUeYg-H35win6TwdxrpYu7Tt5-xoL8aw/gviz/tq?tqx=out:csv`

### Проблема: Старая версия сайта
**Решение**: 
- GitHub Pages кэширует файлы
- Добавьте `?v=2` к URL для сброса кэша
- Или подождите 5-10 минут

## Если ничего не помогло

Создайте issue или напишите мне со следующей информацией:
1. URL вашего сайта
2. Скриншот страницы Settings → Pages
3. Скриншот вкладки Actions с последним запуском
4. Скриншот консоли браузера (F12 → Console)
5. Текст ошибки (если есть)
